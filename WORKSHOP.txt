[h1]Performance Fixes[/h1]
Smoother shop, same game. Fixes stutters in the base game when you work with big, packed storage.

[h2]What it fixes[/h2]
[list]
[*][b]Opening full containers.[/b] All windows share one canvas, so every change redraws every open window. Each container window now gets its own canvas, so a change only redraws that window.
[*][b]Loading and full containers.[/b] Every time an item is added or changes, the game re-lays out the whole inventory it is in, which costs n × n work for n items. Inventories are now laid out once per frame. This cuts seconds of layout from loading a large store.
[*][b]Opening and closing storage windows.[/b] Each time a window opens or closes, the game moves its whole contents between two canvases, which is costly for full storage. Closed windows now stay put, which roughly halves the stutter of the storage-preset hotkey, and a preset's windows now open one per frame so animations keep moving.
[*][b]Instant reopening.[/b] Closing a window used to switch off every slot and item inside it, and reopening switched them all back on. Closed container windows are now simply not drawn, so reopening a full storage window is nearly instant.
[*][b]Trading with nested storage.[/b] To decide whether a customer will buy a container, the game re-checks everything inside it, level after level. The same rule now runs once per item.
[/list]

[h2]What stays the same[/h2]
[list]
[*]Customers accept and refuse exactly what they did before.
[*]Windows look, stack and drag as before.
[*]Each fix can be turned off in the mod's options.
[/list]

[h2]Options[/h2]
Every fix can be switched on or off in the mod's options (gear icon in the Mods menu):
[list]
[*][b]Windows:[/b] Separate canvas per window, Keep closed windows in place, Hide closed windows instantly, Open preset windows one by one
[*][b]Inventories:[/b] Batch inventory layouts
[*][b]Customers:[/b] Fast buyer check
[*][b]Diagnostics:[/b] Log long frames (on), Profile long frames (off)
[/list]

[h2]For troubleshooting[/h2]
Frames over 100 ms are written to Player.log with the window that was just opened, so slowdowns can be traced.

Needs no special permissions. Works on its own or with Demand Highlight. Built for game version 0.46D.

[h1]性能修复[/h1]
店铺更流畅，玩法不变。修复原版游戏在处理大型、塞满的存储时的卡顿。

[h2]修复了什么[/h2]
[list]
[*][b]打开满载容器。[/b]原版所有窗口共用一块画布，任何变化都会重绘所有打开的窗口。现在每个容器窗口有自己的画布，变化只重绘那一个窗口。
[*][b]读档和满载容器。[/b]原版每添加或改变一件物品，就把它所在的整个库存重新布局一次，n 件物品要做 n × n 的工作。现在每个库存每帧只布局一次，读取大型店铺时能省下好几秒。
[*][b]开关存储窗口。[/b]原版每次开关窗口都要把全部内容在两块画布之间搬动，存储越满越慢。现在关闭的窗口原地保留，存储预设快捷键的卡顿大约减半；预设里的窗口改为每帧打开一个，动画不会停住。
[*][b]瞬间重新打开。[/b]原版关闭窗口会停用里面的每个格子和物品，重新打开时再全部启用。现在关闭的容器窗口只是不再绘制，重新打开满载的存储窗口几乎是瞬间的。
[*][b]嵌套存储的交易。[/b]判断顾客是否收购一个容器时，原版会一层一层反复检查里面的所有东西。现在同样的规则对每件物品只执行一次。
[/list]

[h2]保持不变的[/h2]
[list]
[*]顾客收什么、拒什么与原来完全一致。
[*]窗口的外观、叠放和拖动与原来一样。
[*]每项修复都可以在模组选项中关闭。
[/list]

[h2]选项[/h2]
每项修复都可以在模组选项（模组菜单中的齿轮图标）里单独开关：
[list]
[*][b]窗口：[/b]每个窗口独立画布、关闭的窗口原地保留、瞬间隐藏关闭的窗口、预设窗口逐个打开
[*][b]库存：[/b]合并库存布局
[*][b]顾客：[/b]快速收货判定
[*][b]诊断：[/b]记录长帧（默认开）、分析长帧（默认关）
[/list]

[h2]排查问题[/h2]
超过 100 毫秒的帧会连同刚打开的窗口一起写入 Player.log，方便追查卡顿。

不需要任何特殊权限。可单独使用，也可与需求高亮一起使用。适用于游戏版本 0.46D。
